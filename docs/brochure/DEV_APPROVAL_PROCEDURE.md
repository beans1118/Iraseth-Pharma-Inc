**Before any iraseth_dev modification: standalone read-only dry run**

Do not start/restart the updated Flask application against iraseth_dev for this step: application startup calls `ensure_indexes`, including the new SKU comparison-key index. That is a database schema write. This task has created/validated that index in iraseth_test only. No index backfill or active schema operation was performed.

The mapping template now contains exactly 124 unique candidates and 28 columns: PDF/page, name, category, brand/manufacturer, description, features, specifications, image paths/validation/review status, documented models, missing fields, source/approval status and editable staff decisions. Source columns are reference material. Their contents never override the live manifest during draft loading or validation. The generator preserves existing staff-entered cells and refuses to drop unknown candidate keys.

1. Fill only genuine staff data in the mapping CSV. Start with 1-5 records; mark only those `include_in_batch=true` (maximum 30). Enter `staff_approved_sku`, `staff_approved_selling_unit`, and `staff_review_notes`. Set `staff_approved=true` only after personally reviewing those actual mappings; it records staff review, not authorization to modify iraseth_dev.
2. Choose `model_decision`: `use_documented` for the exact printed model, `not_documented` to leave an absent model blank, or `staff_verified` with a genuine `staff_verified_model` plus `model_evidence` referencing supporting supplier documentation. A known printed model cannot be silently replaced. Model evidence is recorded for review/audit, not automatically verified by an external supplier service.
3. Choose `image_decision=omit` or `include`. Inclusion requires correct source association, valid uploads, and `images_approved=true` after visual review. Do not approve missing, oversized or unclear images. Omission is explicit and does not fabricate a replacement.
4. From the repository root, run this command before launching the updated Flask server:

   ```powershell
   backend\.venv\Scripts\python.exe backend\tools\dry_run_brochure_mapping.py --mapping docs\brochure\staff-mapping-template.csv --database iraseth_dev --report docs\brochure\staff-dry-run-review.json
   ```

   The existing `.env` must already name iraseth_dev. The command does not edit environment files, import/start the Flask application, create indexes, issue an approval token, or write database records. It reads catalog identities and uses the shared selection/product validators. An existing report file is refused: use a new report filename to retain review evidence. The current untouched template is correctly blocked because no genuine mappings, selected batch or staff decisions exist. Do not invent data to obtain a successful dry run.
5. Review the successful report's target, source/catalog/selection hashes, exact IDs/units/models/content/image choices, zero quantities and null public prices. Stop here. This read-only report does not authorize an active import. Any source, mapping or catalog change requires another dry run.
